# Jocasta v1: surfaces and their tests

Every user-facing surface of Jocasta v1 (0481), where it lives, the automated test that covers it, and the live check of the 0481 campaign that still has to see it. Made from the campaign's surface map on 2026-10-24 and checked against the repo that day: each `file:line` and test exists.

Live check slices: **UI walkthrough** (sandbox companion over CDP), **security** (0484/0485 re-tests), **perf/reliability/egress** (startup, RAM, idle CPU, kills, log-off, network destinations), **beta** (agents play a full day), **VM** (clean-machine run: install, setup, first run, a thread, uninstall), **voice session** (with him, real speakers and microphone).

Verdict (0481): `pass (automated)` means the automated test named in the row passed on 2026-10-24 (AutoTests: `bun test` over `test/entry.test.ts test/shared test/mcp test/frontier test/setup test/pollers test/graph test/herdr test/watcher test/events test/app test/config test/scripts`: 436 pass, 9 skip, 0 fail; the CDP tests ran in headless Edge), and no live slice saw the surface. `pass (live: <slice> <item>)` means a live report passed it; the item is the report's row number or row name. Fixed findings name the first-round report that raised them. `fail: <finding> (<slice>)` is an open finding. `not testable here: <why>` needs another machine, a real device or him. `pending: <what is left>` has neither an automated nor a live pass yet. Reports: `campaign-AutoTests`, `campaign-UIWalk`, `campaign-SecRetest`, `campaign-PerfReliability`, `campaign-BetaDay` (first round, before the fixes), then `campaign-RetestSurface` and `campaign-RetestFlows` (after the fixes; they win where they cover a surface). The VM run (2026-10-27/28, Hyper-V VM `jocasta-clean`): `VM run1` (user `tester`; `D:/thesis/data/vm/run1-tester/`), `VM run2` (user `tester2`, a fresh profile, with H9; `D:/thesis/data/bench/h9/run2-tester2/`) and `VM retest` (`tester` again, the release rebuilt with the run's fixes).
