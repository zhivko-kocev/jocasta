# 0589 Jocasta moves to omp 18.18.6

- Status: v1
- Kind: product, benchmark
- Phase/slice: program
- Vision: V7, V13
- Date: 2026-11-10

## Question
Claude Fable 5.2 came out on 2026-11-09, after omp 18.18.2, the version 0535 pinned for the harness-OS build and its benchmarks. Which omp does Jocasta run, on his PC and in the VM?

## Facts
Verified 2026-11-10.
- **omp 18.18.2 and Fable 5.2:** its model cache holds `claude-fable-5-2` as discovered from Anthropic's model list, with the wrong card: no reasoning, text only, $10/$50 with $1 cache reads (`~/.omp/agent/models.db`, `model_cache`). Neither settings nor its catalog can fix that:
  - its `modelOverrides` take only `api`, `kind` and `compat` (`config/models-config.ts:38`), so no settings file can correct the card;
  - its catalog binds preserved thinking to the conversation's prefix only for Opus, Sonnet and Haiku 5.5.
- **omp 18.18.3 to 18.18.6**, all released 2026-11-09:
  - 18.18.3: the `ask` tool takes one HTML form (`{html}`).
  - 18.18.4: `--model @role` and `omp auth-gateway` walk that role's fallback chain, and session-title calls are recorded as `model_usage` entries.
  - 18.18.5: the catalog adds Fable 5.2 and Mythos 5.2 ($8/$40, $0.20 cache reads, 1M context).
  - 18.18.6: plan pausing closes an open plan review, and session entries without ids get ids on load. Its catalog binds Fable 5.1 and later's thinking to the prefix (`pi-catalog` `classes/anthropic.kdl:113`).
- Every seam in plan 5.4 and 5.5 was checked against the 18.18.6 npm packages (`D:/jocasta-spikes/omp-18.18.6/seams.md`).
- **Three seams break, all in Jocasta's own code:**
  - **A thread's question:** `sessions.ts` reads `questions[0].question`, but 18.18.6's `ask` takes `{html}`. Every asking thread would read "awaiting you" with no question.
  - **The picker check before `/plan-review` is typed** (`thread-lifecycle.ts` `PICKER_SCREEN`): it matches neither the form's `○ Other: type your own` row nor its footer (`⏎ choose · ↑/↓ move · ⇥ next field · ⎋ cancel`).
  - **A5's count of plan approvals** (`bench/lib/sessions.ts`): approving now writes a second `mode_change` to `none` (`interactive-mode.ts:6957`), so an approval that keeps the context counts twice.
- **Changed but compatible:**
  - today's spend and the ledger now include title calls, as `omp stats` does;
  - session entries without ids get ids on load;
  - herdr's own omp extension labels an `ask` "waiting for user input", because it still reads `questions`. That file is herdr's.
- **Unchanged:**
  - every settings key Jocasta writes (604 settings in both versions, none added or removed);
  - the CLI flags, the session entry shapes, the collab registry and relay, `--restore`;
  - `APPEND_SYSTEM.md` discovery, plan mode's `xd://propose`, the plan-review labels and `/plan-review`;
  - `omp usage --json`, `omp auth-gateway stdio`, the MCP `timeout`.
  - H1's verdict script gives identical verdicts on all 1,486 lines of 0580's corpus under both versions, and omp's git guard gives the same refusals.
- No benchmark row has run on the harness-OS build yet (0533).

## Options
| Option | Pros | Cons |
|---|---|---|
| Update to 18.18.6 now: his PC now, the VM at the weekend's start | Fable 5.2 works this week; his week of use tests the build the weekend measures; four releases of omp fixes | Half a day of checks now; a problem in brand-new releases could show late in the week |
| Keep 18.18.2 until after the benchmarks | No risk to the benchmarks | No Fable this week; the week tests a build that changes right after |
| Update only his PC | Fable this week on his PC | The same checks as updating everywhere; he'd use a build other than the measured one; H4 and A5, run later on his PC, would be on 18.18.6 and the other rows on 18.18.2 |

## Recommendation
Update to 18.18.6 now.

## Choice
omp 18.18.6 everywhere: his PC now, the VM at the weekend's start, and every benchmark row. The three breaks are fixed before the switch. If his week of use shows an omp problem, Jocasta goes back to 18.18.2 before the weekend.

## Reason
He chose "Update to 18.18.6 now".

## Consequences
- Amends 0535: the pinned omp is 18.18.6.
- **A thread's question:** read from the `ask` form the way omp reads it for its own blocked status. The question is the first named field's label; else the text just before the field; else its fieldset's legend; else a lone checkbox's label; else the field's name.
- **The picker check:** `PICKER_SCREEN` also matches the form's Other row and footer.
- **A5:** counts an approval once, as a `mode_change` away from `plan`.
- **Pins and comments:** `PINNED_OMP`, the README, `bench/README.md` (H1's results go under `omp-18.18.6`), the tests and the comments that cite omp's lines move to 18.18.6. Plan 5.4's omp row records this check.
- **Spend:** figures include title calls from 18.18.4 on. Every row runs on 18.18.6, so the rows compare like for like.
- **herdr's label:** herdr's omp extension shows a generic label for an open `ask` until herdr reads the form; the pane still goes blocked and back.
