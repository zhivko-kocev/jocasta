# The full review, 2026-11 (0573)

Before the benchmarks, Jocasta was reviewed from every aspect (0573): security, UI and UX, bugs, refactors and clean code, speed, duplication, the tests, the shipped prompts and config, the benchmark harness and the docs. Fifteen reviewers each took one slice, read the code and the records it rests on, and checked their claims with throwaway scripts kept outside the repo. This file keeps every finding and what became of it.

## How the fixes ran

- Wave 1 (one owner per file): every bug, security and benchmark-validity finding, and every decided visible change (0574–0585), by nine builders: ServiceFix (finished by ServiceFinish), ServerFix, DataFix, FrontFix with CanvasFix, SharedFix, SetupFix, EvalsFix, BenchFix, PromptsFix.
- Wave 2: the refactors. SplitService (service.ts into a facade over 19 modules, its tests into 9 files, `bun test --parallel`, the dead protocol messages), SplitServer (startServer over nine route, stop and close modules), ProductDedupe (one process runner, git runner, poll helper, path key, atomic writer, session reader, line RPC; shared no longer imports the server), HarnessDedupe (one adapter per harness; the bench on the product's helpers), TestHelpers, CallSites (every caller moved onto the shared helpers), ServiceStates (the phase table, finish modes, `Thread` regrouped), Rename (one name, "service", for the process; data keys and files too, old names still read), Docs.
- A docs pass and two record audits then compared every decision of 0574–0586 with the code; the gaps they found were built (SettingsFix, BenchGaps and the integrator's text fixes), a few differences of form got as-built notes in their records, and three questions came back to him: the token file's name (0584's amendment), the keep-alive measurement (0586) and the setup's limit before the harness (0574's amendment).
- Each step kept `bun run typecheck` and `bun run lint` clean; the close ran `mise run check` (867 pass, 8 skip, 0 fail in about 85 s, with `bun test --parallel --timeout 30000`), the Linux suite in WSL (844 pass, 0 fail, after fixing three Linux-only failures: Windows-shaped test paths, and a process-group kill that took a spared process), CI on Windows, Ubuntu and macOS, and a live smoke in a throwaway herdr session.
- A live incident during the fixes: a new test's stand-in processes opened Windows Terminal windows on his desktop (a console program started under a console-less parent gets its own console); every test stand-in now starts hidden, and every spawn in `src/` was checked.
- The live smoke (one real thread, $2.08) passed 7 of 9 checks and found five bugs, each fixed with a test: the popup's "three wrong codes" note, a hosted thread stuck in its handoff step, a start notification lost before any client attached, `project --help` opening the catalog, and a reviewed thread's review lost across a restart. It also showed the tests writing into his real data folder; a test preload now sandboxes every root per test process, and the service's stop waits for its pending writes.
